**兩句可以上台的話**：
1. **合成的遙測和原生的一樣無偏**——中位數比值每個窗長都是 0.97–1.02，兩個平面都是。

候選解釋都沒驗證：bmv2 的 `random()` 每包可能不獨立（對定速流，systematic 取樣的變異數

又一次證明量子是 per-flow——現在有四個值（1490／1490／1494／1506）。

**拓撲差異不影響這個對照**（但要主動講）：P4 跑 4-host、OVS 跑 128-host，

取樣精度只由該鏈路的樣本數決定，與 host 數無關。

#### 以下是原本的規劃與約束（保留，它解釋了為什麼要這樣跑）

**先確認一件事：這個對照在方法上是成立的。** 兩邊都是 **1/256**，我查證過：
- P4：`ndtwin_switch.p4:52` `const bit<16> SAMPLE_RATE = 256`，註解明寫
  「Matches OVS's sampling=256 so the kernel's rate arithmetic is [unchanged]」
- OVS：`testbed_topo.py:136` `sampling=256 polling=0`

所以 `196√(1/c)` 的理論地板兩邊共用，量子公式 `256 × frame × 8` 也共用。**同一把尺量兩個平面。**

#### 🔴 但是負載對不起來，這會決定要跑哪一顆 build

sFlow 精度**只由樣本數決定**，而樣本數 = 速率 × 窗長 ÷ 量子。所以**負載必須對齊**，否則
量到的差異全是負載差異。而 bmv2 有吞吐天花板：

| 目標負載 | stock bmv2（~40 Mbps 天花板） | 對應的 1s 窗理論誤差 |
|---|---|---|
| **200 Mbit/s**（對齊 run A） | ❌ **物理上做不到**，天花板的 5 倍 | ±24% |
| **20 Mbit/s**（對齊 run B） | ✅ 可以（零損區 ≤25 Mbps） | ±76% |

**所以**：
- **對齊 run B 的 20 Mbit/s 這一點，stock build 今天就能跑**，而且它是估計器**壓力最大**的區間
  （c 最小），最能看出 P4 的合成路徑有沒有引入額外誤差。**建議先跑這一點。**
- **要對齊 run A 的 200 Mbit/s，必須換 fast build**（`bmv2_binary_override`，
  460–530 Mbps 天花板）。可行，但**換 build 本身變成一個變因**要在報告裡講。

#### 這一輪真正該問的問題（比「誰比較準」好得多）

兩邊取樣率相同 → 理論預測**兩邊應該一樣**。所以「哪個平面比較準」不是好問題，答案理論上是「一樣」。

**好問題是**：P4 的**合成路徑**（pipeline clone → CPU port → proxy → 合成 sFlow v5 → UDP:6343）
有沒有引入 OVS 的**交換機內建路徑**沒有的偏差或遺失？

- 如果 P4 也坐在 `196√(1/c)` 上 → 結論是「**兩個資料面上是同一把尺**」，
  這比任何一邊單獨的結果都強，而且它直接支撐簡報的核心主張（上層零修改）。
- 如果 P4 不在線上 → 那是一個**發現**，而且是合成路徑特有的。

**兩種結果都值得上台。** 這是設計得好的實驗的特徵。

## 3. Future work

### 3-A 現況

Page 42 目前是「**未完成事項**」——誠實列出沒做完的東西（Phase 3、已知缺陷、刻意延後的決定）。
那**不是 future work**，那是 known limitations。兩者在教授場合的作用不同：
- 未完成事項回答「你還欠什麼」
- future work 回答「這件事接下來往哪走」

**目前簡報只有前者。** 這一節建議補的是後者。

### 3-B 候選，依「上台好不好看」排序

#### 🥇 1. 併發控制：兩條路都走不通，而原因已經定位

**這是最像研究題目的一條。**

現況（已實測）：
- **悲觀鎖沒有 owner 概念**——`release_lock` 只檢查鎖存不存在（不存在回 412），**不看誰持有**。
  實測：A 拿到鎖回 200；B（另一條連線、零憑證）release 同型別回 **200 released**，然後 B 直接拿到鎖。
  七個元件共用這組鎖。
- **樂觀併發控制被 F-5 擋住**——commit 失敗偵測不到，所以「重試」沒有觸發條件。

**為什麼這條最好**：它不是「我們沒做」，而是「**我們知道兩條標準路徑各自被什麼擋住，
而且知道解鎖的前置是哪一個**」（修 F-5 是樂觀 CC 的唯一前置）。
再接上 Statesman 的 observed/proposed/target 模型當文獻錨點，這條就從工程待辦
變成一個有形狀的設計問題。

**風險**：要講「鎖沒有 owner」就等於在台上講一個安全性缺陷。但 Page 42 已經寫了它，
所以問題不是講不講，是**放在哪一段講**——放在 future work 比放在「未完成」好看得多。

#### 🥈 2. `topology_manager.py` 需要拆（1,516 行）

`slide potential modification.md` 已經把論證做完了。最強的一點：
**這個類別內部有兩把彼此獨立的鎖**（`_net_lock` 護圖、`_liveness_lock` 護存活簿記），
而 `:288` / `:306` 的註解明寫兩者「never held at once」。
**一個類別需要兩把互不相干的鎖，通常就是兩個類別。** 這是現成的證據，不是主觀評論。

**為什麼值得放**：一整節在講 baseline 的缺陷，**自己的碼也交出一條結構性待改項**，
直接修掉「功勞與缺陷不對稱」那個已知問題。

#### 🥉 3. 非同步回報：從 200 queued 到 completion handle

程式碼註解自己下的結論：
> Reporting per-entry status to the caller needs either a synchronous path or a completion
> handle — **an architectural decision, not a wording one**.

**這是 future work 該長的樣子**：已經分析清楚、有明確的兩條路、刻意沒做、理由寫下來了
（202 更準確但會弄壞檢查 exactly-200 的 caller，而那是每個寫入 app 都在用的端點）。

**加分細節**：兩個會寫 flow 的 app **都把 response 丟掉**，所以就算現在改成 202 也沒人會看。
這說明修法不只是 kernel 單邊的事——**是七個元件的契約問題**。這讓它更像研究問題而非 bug。

#### 4. Per-flow 精度：5-tuple 三層都缺

- P4 pipeline **有** `flow_5tuple` 表且已接進 pipeline
- proxy 沒接
- **TE app 自己也只送 `ipv4_dst`**（帶著 `# TODO: Change to match 5-tuple in HPE`）

**為什麼值得放**：它是**能力**的 future work 而非修 bug——
「per-flow TE」是一個新功能，而**資料面那一層已經準備好了**。
從投影片的角度，這條可以配一張圖：三層裡兩層缺，而缺的是最容易補的兩層。

⚠️ **同時它是一個必須講清楚的限制**：報告**不能宣稱** per-flow TE。
放進 future work 正好是誠實處理它的方式。

#### 5. P4 側的遙測精度（本分析 1-C 那一輪）

如果 ⑥ 那一輪沒跑，它自然就是一條 future work，而且**是有具體實驗設計的那種**：
負載對齊、build 選擇、預期結果、兩種結果各自的意義（1-C 全寫好了）。
「已經設計好只是還沒跑」的 future work 比「應該要研究一下」強得多。

#### 6. LLDP 調參（已有實驗設計，在 `KNOWN-ISSUES.md` §D-2）

關鍵洞見值得單獨講：**決定值不值得的數字是誤判率，不是偵測時間**——
偵測時間縮 beacon 必然會降，那不是問題；問題是誤判率會不會跟著上去。
另外有兩個結構性限制已經找到：`LINK_BEACON_TIMEOUT_S` 與 watchdog 間隔**都從 beacon 間隔衍生**
（改一個動三個），而 `kLldpFreshSeconds = 12.0` 是 **C++ 常數**，跨語言。
**而且修正窗口由 30 秒 poll 決定，縮 LLDP 不會改善它。**

#### 7. P4 在 128 台上沒測過

08-17 那輪**刻意**不做第四格（只驗交互作用）。配上文獻的「>64 台崩壞」，
這條是一個**邊界清楚**的問題：我們在 10 台，文獻說 64 台是邊界，中間沒人量過。
`p4_testbed_topo.py` 自己的註解寫著 *"128 hosts in BMv2 might be too heavy"*。

### 3-C 建議的取捨

**一頁放三條，不要七條。** 建議 **1（併發）＋ 2（拆檔）＋ 3（非同步回報）**：
