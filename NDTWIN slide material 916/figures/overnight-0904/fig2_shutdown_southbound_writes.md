## 1. The reproduction

1500 flow entries POSTed to
`/ndt/install_flow_entries_modify_flow_entries_and_delete_flow_entries`
(the only endpoint that accepts a batch — `install_flow_entry` wraps its whole
body as a single entry, `HttpSession.cpp:889-901`, read directly, 🟢). 0.303 s
later, `kill -INT` on the kernel's own child pid.

The shaded band on the chart (0.595 → 11.338 s, 10.7 s) is the gap between the
kernel printing that it has stopped and the process actually disappearing, and
`kernel.log`'s own string counts across that whole window are `dropping`=0,
`FlowDispatcher`=0, `still_present`=0, `did not take effect`=0, `withholding`=0 —
**no log line anywhere says this southbound work is still in flight.** The only
evidence it happened is the Ryu-side write timestamps and the WARN line that
finally reports the batch result 10.7 s after "Exiting."

`.test_run/pids/kernel.exit`: `status=0 signal=none reason=exited cleanly` — this
is the **SIGINT** path; `ndt down`'s SIGTERM path is the opposite in both
directions (kills instantly at `status=143`, and drops all 1500 queued entries
without a trace, per the same round's T-1 note). Both are in
rounds/03-R2-concurrency.md §3-6.

## 3. The idle baseline reference line (🟡 read, not run this round)

The dotted line at 2.5 s is **not** a measurement from tonight's binary or this
round — it is a scale reference pulled from a different round to show that 11.3 s
is far outside normal shutdown time, not an artifact of shutdown always being
slow. Source: `doc/audit/2026-09-02_live-round/B5-REPORT.md` §6 (test labeled
`FINDINGS #27`, also documented in `tests/test_KernelStopIsBounded.cpp`), a kernel
built from git rev `6283ff5e` — **a different build than tonight's
`cca5e3e4ebc42358`**, and it measures SIGINT on an otherwise-idle 10-switch bmv2
fabric with nothing queued, not a 1500-entry batch. Its own table:

| run | condition | duration |
|---|---|---|
| post_int_idle_1 / _2 / _3 | idle | 2.40 s, 2.40 s, 2.53 s |
| post_int_long | idle, 20 s uptime | 2.40 s |
| post_int_fast | idle, 1 s uptime | 6.40 s (outlier) |
| post_int_busy_2 | requests in flight | 3.00 s |
| post_int_busy_1 | requests in flight | **81.09 s** |

The chart's "≈ 2.5 s" is the four idle runs excluding the 6.40 s outlier
(2.40–2.53 s); rounds/03's own paraphrase ("#27 記的 idle 2.4–3.0 s") folds in
`post_int_busy_2`'s 3.00 s, which is not actually an idle run. Treat the dotted
line as "same order of magnitude as a normal idle shutdown," not as a controlled
same-binary comparison — that comparison does not exist yet.

## 4. Caveats

- This is a **1/1** observation of the 1500-entry SIGINT path — the step kills
  the kernel, so the round did not repeat it. The mechanism (stop-flag not read
  inside the southbound-write loop) is a class of bug the same round's §3-1/§3-2
  already show acting on other paths, and `main.cpp:504-508`'s stop sequence
  reportedly does not include this worker at all (🟡 read, not re-verified this
  round — see rounds/03 §4 Q3), but the 10.7 s number itself is a single run.
- The batch's `dispatched=1500 / succeeded` counters are not shown here; see fig3's
  companion for why `succeeded` is not evidence of a real switch-side change on
  its own.
